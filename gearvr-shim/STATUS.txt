Gear VR -> PhoneXR shim
=======================

Gear VR games render through VrApi (libvrapi.so) from the Oculus Mobile SDK. That libvrapi.so is
only a loader: it looks for the Oculus system driver (com.oculus.systemdriver), which existed
only on Samsung phones, and without it the game does not start. The shim builds its own
libvrapi.so with the same exports as the original and performs the calls through OpenXR on the
PhoneXR runtime (Monado). There is no "this is a Samsung" check in it, so vrapi_Initialize
succeeds on any phone with PhoneXR.

Layout
------
src/xr_backend.{h,cpp}   OpenXR: instance, a session on the game's EGL context, frames, swapchains,
                         head and eyes, controllers, CLOCK_MONOTONIC <-> XrTime conversion.
src/vrapi_system.cpp     vrapi_Initialize/Shutdown, system properties and statuses, tracking spaces,
                         Guardian, performance, stubs for Vulkan and the other exports.
src/vrapi_frame.cpp      vrapi_EnterVrMode/LeaveVrMode, GetPredictedDisplayTime, GetPredictedTracking(2),
                         WaitFrame/BeginFrame, SubmitFrame2 and the old SubmitFrame, PollEvent.
src/vrapi_swapchain.cpp  vrapi_CreateTextureSwapChain(…4): the game's GL textures; when a frame is
                         submitted the chosen image is copied (glBlitFramebuffer) into the OpenXR swapchain.
src/vrapi_input.cpp      controllers: in Gear VR mode the right PhoneXR controller = Gear VR Controller
                         (trigger, touchpad = stick + A, back = B); in Quest mode — two Touch controllers.

The exports were checked against the original libvrapi.so 1.50 (arm64): all 104 symbols are there.

Which device the game sees is set on the phone:
  adb shell setprop debug.phonexr.vrapi.product gearvr   (the default, Galaxy S8 + Gear VR)
  adb shell setprop debug.phonexr.vrapi.product go
  adb shell setprop debug.phonexr.vrapi.product quest
Logs: adb logcat -s PhoneXR-VrApi PhoneXR-GearVR

Building
--------
  cmake -S gearvr-shim -B gearvr-shim/build -G Ninja -DCMAKE_BUILD_TYPE=Release \
    -DCMAKE_TOOLCHAIN_FILE=$ANDROID_HOME/ndk/<version>/build/cmake/android.toolchain.cmake \
    -DANDROID_ABI=arm64-v8a -DANDROID_PLATFORM=android-26
  cmake --build gearvr-shim/build
For 32-bit games, the same with -B gearvr-shim/build32 -DANDROID_ABI=armeabi-v7a.
Result: gearvr-shim/build/assets/libvrapi.so and libvrapi32.so (the PhoneXR app picks them up there).

Porting a game:
  python3 sdk/tools/phonexr_port.py game.apk
The tool replaces lib/arm64-v8a/libvrapi.so with the shim, adds libopenxr_loader.so,
fixes up the manifest and signs the APK.

VrApi headers
-------------
A copy of VrApi from the Oculus Mobile SDK 1.50 lives in third_party/VrApi (Include, Libs, Projects).
The folder is in .gitignore and never reaches the repository: the SDK is distributed under the
Oculus license and may not be published. Without it the build stops; the other way is
-DVRAPI_ROOT=<sdk>/VrApi.

Untested and unfinished
-----------------------
* The shim has not been run on a phone with a real game yet. It builds without warnings,
  but the colors, frame timings and Unity/Unreal behavior have to be checked on a device.
* 32-bit games (armeabi-v7a, armeabi) are built as a separate copy of the shim
  (libvrapi32.so) with the official 32-bit Khronos OpenXR loader 1.1.63
  (app/src/main/assets/libopenxr_loader32.so). The 32-bit mode is untested on a device.
* OpenGL ES only. vrapi_Initialize rejects Vulkan games.
* Of the layers, only the projection one is drawn (Projection2 and the layers of the old SubmitFrame).
  Cylinder, Cube, Equirect, LoadingIcon and FishEye are skipped: loading screens,
  OVROverlay overlays and 360 backgrounds disappear.
* Video swapchains on an Android Surface (vrapi_CreateAndroidSurfaceSwapChain) are not supported:
  360 video players will show no image.
* The structures come from VrApi 1.50. Games built against very old SDKs (2015–2016) may have used
  a different structure layout and may crash.
* The touchpad and the back button on the Gear VR headset itself reached the game as Android events
  (keys and touches), not through VrApi. The shim does not provide them.
* There is no hand tracking through vrapi_GetHandPose (PhoneXR hands arrive as controllers),
  no haptics, and the floor and Guardian are not tracked (the floor is assumed 1.6 m below the eyes).
* If the GL driver has no GL_EXT_sRGB_write_control, 8-bit frames may look
  brighter than on Gear VR.

What the shim will not do
-------------------------
Bypass the Oculus Platform purchase check (libovrplatformloader.so). PhoneXR still prepares and
installs such games, but it does not touch the check library: if the game does not work without
a purchase, it will not start; if the check does not matter, the game is playable.

The driver without patching (com.oculus.systemdriver)
-----------------------------------------------------
The libvrapi.so inside a game is only a loader: vrapi_Initialize opens the
com.oculus.systemdriver package, calls DriverLoader.load64 / load64Ext (load32 / load32Ext in
32-bit games) with (the game's Context, the driver's Context, 5 int[, long]) and gets the address of a
"function by name" function. With it the loader fills its own table by name (vrapi_Initialize,
vrapi_SubmitFrame2, … — the same ones as the exports); the package signature is not checked.
The phonexr_vrapi target builds the same VrApi plus src/vrapi_driver.cpp (get_proc and the JNI
procAddress), and vrapi-driver/build_driver_apk.py packs it together with the OpenXR loader
(arm64 and arm) into PhoneXR VrApi Driver → app/src/main/assets/runtime/phonexr-vrapi-driver.apk.
Games with targetSdk 30+ cannot see other packages: PhoneXR launches them through the runtime's
GameLauncher, which goes through the driver's GameLauncher, and the game receives the URIs of both
packages, which makes them visible.
Checked with the original loader 1.1.50 from the SDK: arm64 and armeabi-v7a — vrapi_Initialize = 0.
