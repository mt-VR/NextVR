PhoneXR: Lua, Unity and Godot
=============================

The general idea
----------------
PhoneXR starts tracking before the game and sends the latest hand/Joy-Con state over UDP to
127.0.0.1:42425. The PH5 line format is described in protocol.txt. For ordinary VR poses and
buttons it is better to use OpenXR; UDP is for raw gestures (pinch, palm_to_face, palm position).

Unity
-----
1. Enable the OpenXR Plugin and Android/ARM64.
2. Add the Oculus Touch / Khronos Simple Controller profile.
3. For raw gestures create a UdpClient(42425), read only the last packet in Update and
   parse PH5 as in protocol.txt. Read on a separate thread and call the Unity API in Update.
4. In the AndroidManifest add the queries and the VR features from manifest.txt as optional.

Godot 4
-------
1. Enable OpenXR and the Android arm64-v8a export.
2. Bind the hand actions through the OpenXR action map.
3. For PH5 use PacketPeerUDP: bind(42425, "127.0.0.1"), then in _process() drop the old
   packets and parse the last get_packet().get_string_from_ascii().
4. Add the snippets from manifest.txt to the Android build template.

Lua
---
For an engine with LuaSocket open a non-blocking UDP socket on 127.0.0.1:42425:

  local udp = require("socket").udp()
  udp:setsockname("127.0.0.1", 42425)
  udp:settimeout(0)
  local packet = udp:receive()

Parse packet as PH5 following protocol.txt. In Solar2D/LÖVE or your own C/C++ engine without
LuaSocket, include runtime/phonexr_input.h and expose phonexr_state to Lua through a regular binding.
Pass the five *_curl fields as numbers 0..1 so that each finger animates independently.

Quest and Pico
--------------
Your own or legally distributed Quest/Pico APKs can go into the PhoneXR store.
PhoneXR downloads the APK itself, stops the headset hardware features from being required, puts in
its own OpenXR loader, signs it and opens the system install prompt. The closed Meta/Pico runtime
and purchase checks are not bypassed; such games need an official port from the developer.
