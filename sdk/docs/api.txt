PhoneXR Developer API
=====================

A PhoneXR app is built for PhoneXR, not for Quest. The main graphics API is OpenXR;
the additional PhoneXR Input API reports raw gestures and the Joy-Con.

1. OpenXR
   Use the standard Android OpenXR loader and the Oculus Touch/Khronos Simple Controller profiles.
   PhoneXR Runtime provides the head, the left/right hand, poses, trigger, squeeze, A/X, B/Y,
   menu and the sticks. Copy the required elements from manifest.txt into your manifest.

2. PhoneXR Input API
   Transport: UDP 127.0.0.1:42425, ASCII, packet version PH5, up to 60 updates/s.
   Ready-made clients: src/main/kotlin/com/phonexr/sdk/PhoneXRInput.kt for Kotlin/Java and
   runtime/phonexr_input.h for C/C++. The full schema is in protocol.txt.

   In PH6 each hand also carries thumbCurl/indexCurl/middleCurl/ringCurl/pinkyCurl
   (in C: thumb_curl/index_curl/middle_curl/ring_curl/pinky_curl), values 0..1. That lets the
   app build its own finger pose instead of picking one fixed gesture.

3. Lifecycle
   The user launches the game from PhoneXR. PhoneXR turns on the camera and the API stream before
   the Activity starts. The game opens port 42425 non-blocking, always takes the last packet and
   keeps working through OpenXR when the extra stream is temporarily unavailable.

4. Compatibility
   Build arm64-v8a, do not require a specific headset model, do not embed a Quest/Pico store check.
   Check 3DoF and 6DoF through the PHONEXR_FLAG_SIX_DOF flag and let the user play
   in both modes.

5. Publishing
   Release an APK or a .pxr plus the store JSON with name, url, icon, description and size. PhoneXR
   downloads it, prepares it and hands the APK to the system installer. Android requires the package
   to be installed; running an APK as a file inside another app without a container is impossible.
